# 工业路由器装配 MES 解决方案蓝图

## 1. 文档控制

| 属性 | 内容 |
|---|---|
| 文档编号 | MES-SOL-001 |
| 版本 | 0.1 |
| 状态 | 目标方案基线候选 |
| 架构形态 | 模块化单体 + 关系型当前状态 + 只追加制造事件 |
| 部署形态 | 单厂私有化 Docker Compose |

## 2. 方案摘要

方案以“成品 SN 全过程追溯”为第一价值，不以页面数量或经营大屏作为完成标准。ERP 负责计划和业务财务权威，MES 负责执行规则、在制状态和制造事实；两者通过幂等消息契约协作。系统在同一 SQL Server 中维护便于查询的当前状态和不可覆盖的制造事件，避免纯 CRUD 丢历史，也避免完整事件溯源带来的不必要复杂度。

## 3. 设计原则

1. **证据优先**：公开资料不足的工艺细节保持可配置和待确认。
2. **身份优先**：所有执行事实最终可关联到成品 SN、订单和执行快照。
3. **历史不可覆盖**：制造事件、测试、质量、物料和集成记录只追加；更正有前后关系。
4. **状态与事件并存**：状态服务当前判断，事件服务追溯、审计和解释。
5. **职责明确**：ERP 计划权威、MES 执行权威、仓储责任交接互不冒充。
6. **事务内聚**：一次业务动作的校验、状态、事件和 Outbox 在同一事务完成。
7. **先纵向闭环**：优先打通订单到谱系的深链路，再扩展大屏和外围模块。

## 4. 业务上下文与系统边界

| 上下文 | 权威数据/职责 | 与 MES 的关系 |
|---|---|---|
| ERP/计划系统 | 产品、物料、计量单位、生产订单、计划数量、库存总账和财务结果 | 下发主数据/订单，接收完工、耗料、报废等结果 |
| MES | 工艺、工位、追溯策略、测试规范、生产执行、WIP、制造事件和质量处置 | 执行权威和单件谱系中心 |
| 仓储/WMS 或仓储岗位 | 物料责任交接、成品接收；若有 WMS 则管理库位和仓内流程 | 与 MES 交换交接和接收回执 |
| 身份/标签/证书系统 | SN、MAC、IMEI、证书和标签模板的授权分配 | 向 MES 提供身份并接收使用/作废事件 |
| 测试设备/文件存储 | 原始测试数据、设备结果和报告文件 | MES 保存结构化测量和不可变报告引用 |

## 5. 逻辑架构

### 5.1 体验层

- **计划与管理端**：生产订单、物料、质量待办、追溯、审计和集成对账。
- **工位执行端**：工位上下文、扫码、装配绑定、固件/配置、测试、缺陷报告和明确防错。
- **运维入口**：健康、版本、迁移状态、消息队列、日志关联和恢复验证。

### 5.2 应用与领域层

| 模块 | 核心职责 | 关键边界 |
|---|---|---|
| Integration | Inbox、Outbox、适配器、回执和对账 | 不允许适配器直接写业务表 |
| ProductionOrders | 订单生命周期、下达快照、暂停、短结、完成和关闭 | 不拥有 ERP 主数据真相 |
| Execution | START_WIP、工位执行、防跳站和当前 WIP | 不承担质量处置审批 |
| Identity | 成品/部件身份、号源、标签、绑定/解绑和作废 | 不越权生成受控标识 |
| Materials | 交接、发料、耗用、退料、冲正和余额投影 | 不扩展为完整 WMS/MRP |
| FirmwareAndTests | 固件/配置、测试规范、测试执行、测量和原始报告 | 复测不覆盖失败记录 |
| Quality | 不合格、质量保留、处置、返工、复测条件和报废 | 操作执行与审批职责分离 |
| Completion | 合格完工、仓储交接和订单数量平衡 | 完工不冒充 ERP 入账 |
| Genealogy | 按 SN 聚合订单、快照、事件、物料、测试、质量和回执 | 只读聚合，不创造制造事实 |
| IdentityAccessAudit | 组合角色、能力、职责分离和业务审计 | 系统管理员不天然拥有业务审批 |

### 5.3 基础设施层

- SQL Server 保存业务当前状态、不可变事实、消息和审计。
- 文件存储保存原始测试报告、导出证据和备份，数据库只保存校验值与引用。
- 后台服务负责 Outbox 投递、重试、死信、对账任务和保留策略作业。
- Nginx 提供 HTTPS、同源入口和反向代理；API 与数据库不直接暴露到厂区网络。

## 6. 核心领域模型

### 6.1 聚合与实体

| 对象 | 作用 | 关键不变量 |
|---|---|---|
| ProductionOrder | 生产执行的订单边界 | 只有下达快照完整才可投产；有在制不可取消 |
| ExecutionSnapshot | 某订单实际依据 | 含 BOM、路线、追溯和测试的自包含版本化内容 |
| ProductUnit | 某个成品 SN 的当前状态 | 同一受控身份不能同时属于两个开放订单 |
| ManufacturingEvent | 某制造事实 | 确认后不修改；更正引用原事件 |
| MaterialTransaction | 物料责任和数量事实 | 余额不得通过直接改总数产生；不可形成未授权负数 |
| TestSpecification | 批准的测试定义 | 已使用版本不可原地修改 |
| TestRun / Measurement | 一次测试及逐项测量 | 复测为新执行；原失败保留 |
| Nonconformance | 未满足要求的正式记录 | 未处置或未满足条件时保持质量保留 |
| Disposition | 授权的质量决定 | 必须有授权主体、理由和后续要求 |
| InboxMessage / OutboxMessage | 集成可靠性记录 | 幂等业务键唯一；投递状态可重试、可对账 |

### 6.2 生产订单状态

| 状态 | 进入条件 | 允许的主要动作 | 禁止事项 |
|---|---|---|---|
| 已接收 | ERP 消息校验并落入 MES | 评审、排定、下达、取消 | 投产、发料耗用 |
| 已下达 | 执行快照冻结并获准生产 | 发料、START_WIP、暂停、投产前取消 | 静默覆盖快照 |
| 生产中 | 至少一个 SN 已 START_WIP | 执行、质量处理、暂停 | 直接取消 |
| 已暂停 | 计划或异常触发暂停 | 处理在制、恢复、受控短结 | 新投产和正常过站 |
| 执行完成 | 已投产 SN 全部合格完工/报废且无未决保留 | 对账、差异处理 | 新投产、修改执行事实 |
| 已关闭 | 外部回执与差异处理完成 | 查询、导出 | 任何业务写入 |
| 已取消 | 投产前终止 | 查询 | START_WIP |

### 6.3 产品单元状态维度

ProductUnit 不使用一个超大枚举同时表达工序、质量和仓储。至少分离：执行位置/终态、质量保留、仓储交接和外部入账。这样测试失败后仍能准确表达“位于功能测试、处于质量保留、尚未完工”，而不是用一个 `Isolated` 覆盖全部含义。

## 7. 执行快照设计

执行快照在订单下达时物化，至少包含：产品和单位、计划数量、BOM 行及单位用量、物料追溯粒度、路线步骤与顺序、工位能力要求、身份策略、固件/配置要求、测试规范与必测项目、完工门禁和版本来源。快照必须可在源主数据后续变化时独立还原。

已投产后收到 ERP 变更时，系统创建变更提案，比较数量、产品、日期和执行依据影响。无在制时可重新下达新快照；有在制时必须选择仅影响未投产数量、新建订单或受控短结，不允许自动改写已执行 SN。

## 8. 制造事件模型

建议采用通用事件信封与类型化载荷：事件 ID、事件类型、发生/记录时间、工厂、产线、工位、订单、成品 SN、主体、关联事件、相关业务键、载荷版本和载荷。核心事件包括订单接收/下达/暂停/恢复、START_WIP、过站、部件绑定/解绑、固件配置、测试开始/结束、不合格、质量保留、处置、返工、复测、报废、完工、仓储交接和集成回执。

当前状态与事件必须同事务提交。查询页面优先读取当前投影，谱系导出同时读取事实明细。业务审计描述“谁做了动作”，制造事件描述“产品发生了什么”，两者通过业务键关联但不互相替代。

## 9. 物料与谱系模型

| 追溯类型 | 记录时点 | 谱系表现 | 例子 |
|---|---|---|---|
| Serial | 具体部件绑定到成品时 | 成品 SN -> 部件 SN | 主 PCBA、通信模块 |
| Lot | 指定工序实际耗用时 | 成品 SN -> 物料 Lot + 数量 | 外壳批次、连接器批次 |
| Quantity | 批准的工序回冲时 | 成品 SN 或订单 -> 数量 | 螺钉、标签耗材 |

物料事务类型至少包括 TransferIn、IssueToOrder、Consume、Return、Reverse 和 Adjust。每笔事务包含物料、Lot/Serial、数量、单位、来源/目标责任、订单、成品 SN、工序、原因、主体和关联原事务。余额和工单可用量由事务投影，禁止直接修改聚合数字。

## 10. 固件与测试模型

固件/配置记录与普通过站分离，保存包 ID、版本、校验值、配置模板、工具/设备、参数摘要、执行结果和原始日志引用。测试规范定义项目、数据类型、单位、上下限或枚举规则及适用条件。每次 TestRun 下包含多条 Measurement，并可引用设备原始报告。失败测试触发不合格，但不自动决定返工或报废。

## 11. 质量模型

质量闭环分为五个概念：检测结果、不合格记录、质量保留、处置决定、返工/复测执行。返工处置必须指向批准的返工作业或路线版本；让步接收必须有授权和适用范围；解除质量保留必须验证处置要求完成。原失败、处置、返工和复测全部进入谱系。

## 12. 集成架构

### 12.1 入站

ERP 消息先写入 Inbox，唯一键建议由 SourceSystem + MessageId 构成，业务去重可再使用 MessageType + BusinessKey + SourceVersion。处理流程包括结构校验、主数据引用校验、版本/顺序校验、领域命令执行和结果记录。失败保留原始载荷校验值与可读错误，不创建半成品业务记录。

### 12.2 出站

领域事务同时写入 Outbox。后台发送器认领 Pending 消息，设置租约和 Processing，成功后等待或记录业务回执，失败则按退避策略重试；超过阈值进入 DeadLetter。人工重试不新造业务事实，只重新投递同一幂等消息或显式补偿消息。

### 12.3 候选接口清单

| 接口 | 方向 | 业务对象 | 关键要求 |
|---|---|---|---|
| ProductMasterUpsert | ERP -> MES | 产品、单位、版本 | 幂等、版本控制、不可影响已冻结快照 |
| MaterialMasterUpsert | ERP -> MES | 物料、单位 | 幂等、状态和基础属性校验 |
| ProductionOrderUpsert | ERP -> MES | 订单和计划数量 | 下达后变更进入受控变更 |
| MaterialTransferNotice | ERP/WMS -> MES | 物料、Lot、数量 | 与工单发料和耗用分离 |
| ProductionCompletion | MES -> ERP | 合格完工 | 至少一次投递、业务幂等键、回执 |
| MaterialConsumption | MES -> ERP | 耗用/冲正 | 支持序列、批次和数量汇总 |
| ScrapDeclaration | MES -> ERP | 报废 | 与质量处置和订单数量平衡关联 |
| WarehouseHandoff | MES <-> WMS/仓储 | 成品交接 | 不等同于 ERP 财务入账 |

具体字段、厂商 API、认证、批处理/实时方式和错误码均待 ERP 版本与客户接口能力确认。

## 13. 安全与授权

- 本地账号仅作为试点候选，密码使用强哈希；后续可通过适配边界接入 AD/SSO。
- 账号可组合角色，API 按能力授权；前端隐藏按钮不构成安全控制。
- 质量处置、工艺批准、系统管理和操作执行保留职责分离。
- JWT 密钥、数据库密码和 TLS 证书从仓库外注入，发现示例值时生产启动失败。
- 业务审计记录关键动作，但敏感测试文件、证书材料和密码不得进入普通日志。

## 14. 部署与运维

默认在厂内 Linux 主机运行 Nginx、ASP.NET Core API、后台任务和 SQL Server/客户 SQL Server。Nginx 是唯一网络入口并提供 HTTPS；API 和数据库位于内部容器网络，数据库不暴露到厂区客户端。正式环境使用 `Production`、固定镜像版本、外部配置和最小权限账号。

部署按“备份 -> 显式迁移 -> 启动 -> 就绪检查 -> 冒烟测试”执行。每日完整备份、升级前备份并完成恢复演练。日志结构化、带关联 ID 并轮转；制造事件和业务审计不随运行日志轮转删除。试点候选目标为 RPO 24 小时、RTO 4 小时，最终以客户连续性要求为准。

## 15. 数据库演进与测试

EF Core Migration 是唯一结构演进机制。API 不在生产启动时自动建库、删库或装载种子。快速测试可以使用 SQLite，但以下能力必须在临时 SQL Server 验证：空库迁移、上一版本带数据升级、唯一约束、事务回滚、Inbox/Outbox 幂等、并发认领和关键查询。

旧演示数据若无法证明缺失的执行快照、测试或物料事实，只能标记为 Legacy 并只读保留，不得补造历史。开发环境可显式重置演示数据库，但该路径与生产升级严格分离。

## 16. 当前实现差距

| 现状 | 风险 | 目标处理 |
|---|---|---|
| 下达仅保存 BOM/路线 ID 和版本字符串 | 源记录变化后无法还原实际依据 | 物化自包含执行快照 |
| 谱系主要含过站和部件绑定 | 缺固件、测试、Lot、解绑和更正历史 | 建立类型化制造事件和聚合查询 |
| 不合格、隔离、放行混在 ProductSerial 状态和通过记录 | 无法区分发现、保留、处置与复测 | 独立质量对象和门禁 |
| 发料直接影响库存并近似耗用 | 责任与实际装配混淆 | 交接/发料/耗用事务账分离 |
| ERP Outbox 创建即 SimulatedSent | 无失败、重试、回执和对账 | 真实状态机和模拟适配器 |
| EnsureCreated + 开发自动删库 | 无可控升级路径 | Migration + 显式部署步骤 |
| 所有 API 测试使用 SQLite | 无法证明 SQL Server 行为 | 增加容器化 SQL Server 测试 |
| Compose 内硬编码密钥、sa、Development、全开放 CORS | 不满足试点安全底线 | 生产配置门禁和内部网络 |

## 17. 方案限制

本蓝图不证明参考路线是行业统一 SOP，不证明目标工厂一定使用本文接口字段，也不证明候选性能目标和保留年限已经被客户接受。真实落地前必须完成现场价值流、工位、SOP、质量、ERP、设备、网络、数据和运维工作坊，并将结论回写需求台账和 ADR。
