# 工业路由器装配 MES 项目前期交付物索引

## 1. 文档目的

本目录是“单厂工业路由器整机装配 MES 试点候选项目”的项目前期单一事实源。它服务四类使用场景：方案评审、项目立项、实施准备和求职面试。项目尚无真实甲方、现场调研或制造从业者签字，因此所有结论必须区分证据与假设，不能将技术演示称为已落地案例。

## 2. 项目基线

| 项目 | 当前定义 |
|---|---|
| 项目名称 | 工业路由器装配 MES 试点候选项目 |
| 目标客户画像 | 已有用友或金蝶 ERP，车间主要依赖 Excel、纸单和扫码枪的中国中小工业电子制造企业 |
| 试点范围 | 单厂、单条人工整机装配线，从已测 PCBA 投入到合格整机完工与仓储交接 |
| 第一价值 | 按成品 SN 还原工单、工艺、物料、固件、测试、质量和集成回执的全过程谱系 |
| 技术基线 | ASP.NET Core / .NET 10、Vue 3、SQL Server、Docker Compose |
| 当前可信度 | 领域救援和方案设计中；旧版本仅有演示级技术验证 |
| 明确不宣称 | 已签约、已上线、已现场验收、已完成真实用友/金蝶联调 |

## 4. 证据等级

| 等级 | 含义 | 允许的表述 |
|---|---|---|
| A | 标准或高可信一手资料直接支持 | “标准定义/资料明确支持” |
| B | 由标准分层、接口模型或已确认边界合理推导 | “本方案据此推导” |
| C | 为使候选系统可演示而采用的样板假设 | “候选配置，待现场确认” |
| D | 尚无充分依据，仅作为待澄清项 | “未决定，不进入生产承诺” |

## 5. 可信度状态

`未验证 -> 已实现 -> 技术验证通过 -> 制造从业者评审通过 -> 真实现场验证通过`

本项目在没有行业评审和现场试点前，最高只能标记为“技术验证通过”。任何材料中的“验收”均指预先约定的技术验收门禁，不表示真实客户已签字。

## 6. 使用规则

- 业务范围、术语和状态以根目录 `CONTEXT.md` 与 ADR-0011 至 ADR-0028 为准。
- 公开行业依据以 `docs/research/industrial-router-assembly-traceability.md` 为准。
- 明细编号以项目管理台账为准；Word 和 PPT 只承载决策所需摘要。
- 需求变更先更新需求台账和 ADR，再修改实现，不允许只改页面或数据库。
- 未经现场确认的产量、节拍、测试阈值、设备协议、保留年限和接口字段不得写成既定事实。
