# 工业路由器装配 MES 项目实施与治理计划

## 1. 文档控制

| 属性 | 内容 |
|---|---|
| 文档编号 | MES-IMP-001 |
| 版本 | 0.1 |
| 状态 | 实施候选基线 |
| 计划周期 | 5 至 6 周全职救援开发；真实客户项目需重新估算 |

## 2. 实施策略

保留现有 .NET、Vue 和 SQL Server 技术骨架，在同一仓库按纵向业务切片增量替换错误模型。每个阶段同时完成领域规则、数据库迁移、API、必要 UI、自动化测试和证据，不采用“后端全写完再补前端”或“先堆页面再补规则”的分层瀑布。

旧二期经营大屏和工作台扩张保持暂停，直到订单、执行快照、事件、物料、测试、质量和集成事务内核完成。旧 API/UI 可以复用，但不得为了兼容错误语义而保留直接发料即耗料、自由文本放行或创建即发送成功等行为。

## 3. 阶段计划

### 3.1 R0 救援基线

目标：统一项目定位、业务边界、证据等级、需求编号、架构决策和发布门禁。

主要交付：项目前期文档、需求追踪矩阵、旧验收声明降级、高危依赖处置、当前代码基线和演示快照。

退出条件：所有新增工作能关联需求 ID；旧二期规格不再驱动实现；关键假设进入台账。

### 3.2 R1 可信数据底座

目标：建立可升级、可验证和可安全部署的数据基础。

主要交付：EF Core Migration、SQL Server 测试夹具、生产配置校验、显式演示数据命令、执行快照表、旧数据 Legacy 策略。

退出条件：空库迁移和上一版本带数据升级通过；API 不再自动删库；示例密钥在生产启动失败。

### 3.3 R2 制造执行内核

目标：完成从 ERP 订单到成品 SN 在制的可信主干。

主要交付：生产订单生命周期、受控变更、身份来源、START_WIP、版本化路线、防跳站、制造事件、物料事务账。

退出条件：订单下达后模板变化不影响快照；有在制不可取消；物料交接/发料/耗用可分别对账。

### 3.4 R3 测试、质量与谱系

目标：形成项目最核心的单件全过程追溯能力。

主要交付：固件记录、测试规范、测量、原始报告引用、不合格、质量保留、处置、返工、复测、报废和谱系导出。

退出条件：正常完工、失败返工复测和报废三条场景可重复执行，原失败记录不可覆盖。

### 3.5 R4 企业集成闭环

目标：证明 ERP/MES 边界具备可靠消息和对账能力。

主要交付：Inbox、Outbox 发送器、租约/重试、死信、回执、对账工作台和正式模拟 ERP 适配器。

退出条件：重复入站不重复建单；出站失败后可恢复；制造完工、仓储接收和 ERP 入账状态可分辨。

### 3.6 R5 一线工作流 UI

目标：让计划、工位、质量和追溯用户可以完成核心工作，而不是展示 API 功能清单。

主要交付：订单工作台、工位执行端、质量待办、单件谱系、集成对账、浏览器 E2E 和视觉缺陷修复。

退出条件：四条验收场景可在浏览器完成；错误提示能指导恢复；权限拒绝由服务端执行。

### 3.7 R6 可交付与证据

目标：形成可部署、可恢复、可演示和可解释的技术验证版本。

主要交付：HTTPS Compose、升级/回退运行手册、备份恢复演练、版本化证据包、方案汇报材料和面试问答。

退出条件：所有技术验证门禁通过，未验证项和现场前置条件完整，不出现“已落地”误导表述。

## 4. 项目治理

### 4.1 会议与节奏

| 机制 | 频率 | 参与人 | 输出 |
|---|---|---|---|
| 每日执行同步 | 每工作日 15 分钟 | 开发、测试、项目经理 | 当日目标、阻塞和风险变化 |
| 需求/蓝图工作坊 | 每个新领域切片前 | 业务、工艺、质量、IT、方案 | 已确认规则、假设、待办和 ADR |
| 阶段演示 | 每阶段结束 | 发起人、关键用户、项目组 | 场景证据、差距和阶段决定 |
| RAID 评审 | 每周 | 项目经理、责任人 | 风险应对、问题升级和依赖承诺 |
| 发布评审 | 每版本 | 技术、测试、业务代表 | 门禁结果、回退条件和发布建议 |

### 4.2 决策和升级

- 业务范围和验收冲突由项目发起人/业务负责人裁决。
- 工艺、测试和质量规则分别由工艺与质量负责人批准。
- 架构和数据一致性由技术负责人提出方案，重大取舍形成 ADR。
- 影响范围、周期或数据的变更必须进入变更请求；紧急修复事后补齐记录和验证。
- 阻塞超过一个工作日或影响里程碑时，由项目经理升级到对应决策人。

## 5. 需求与变更控制

1. 新需求先登记 ID、业务价值、来源、证据等级和验收条件。
2. 项目组评估范围、数据、接口、安全、测试、培训和发布影响。
3. 业务负责人决定批准、延后、拒绝或拆分。
4. 批准后更新需求基线、WBS、风险、ADR 和验收追踪。
5. 实现完成后必须提供自动化和人工证据，不能仅凭开发自测关闭。

## 6. 数据与集成准备

真实项目启动后，应在开发前完成以下清单：ERP 产品/版本、接口文档和技术账号；物料/产品编码和单位；BOM 来源与版本；生产订单/完工/耗料/报废单据；身份和标签责任；错误码和重试政策；样例报文；历史数据范围；主数据质量报告；网络与证书。

数据清洗和接口开发并行推进。代码完成不代表接口可上线，只有主数据映射、业务规则、幂等键、错误处理、对账和回执全部验证后才可进入 UAT。

## 7. 环境与配置管理

| 环境 | 目的 | 数据 | 变更规则 |
|---|---|---|---|
| Development | 开发和快速调试 | 显式演示种子，可重置 | 允许本地工具，不等同生产 |
| IntegrationTest | SQL Server 自动化 | 每次独立临时数据 | CI 创建和销毁 |
| Demo | 方案演示和面试 | 标记为非生产的固定场景 | 只由版本化脚本装载 |
| UAT | 关键用户验收 | 脱敏或专门构造的数据 | 变更受发布流程控制 |
| Production | 真实运行 | 生产业务数据 | 无种子、外置密钥、显式迁移 |

配置项、数据库迁移、接口映射、测试规范和工艺版本必须可追踪到发布版本。生产热改必须形成受控配置变更和审计。

## 8. 培训与变更管理

培训按角色和场景组织：计划员掌握订单生命周期和变更；操作工掌握工位、扫码、防错和异常报告；工艺/质量掌握版本、处置和复测；IT 掌握部署、账号、日志、备份和恢复。培训必须使用 UAT 场景，完成后记录出席、实操结果和遗留问题。

上线前明确纸单/Excel 的去留、过渡期双轨规则、系统不可用时的手工应急记录及恢复后补录审批。禁止长期无责任人的“双轨运行”，否则 MES 无法成为执行权威。

## 9. 切换与上线准备

### 9.1 上线前检查

- 需求和范围已批准，未决高风险有明确接受人。
- 主数据、执行快照、身份、路线、测试和质量规则已由责任人确认。
- UAT 关键场景通过，严重缺陷为零，已知限制已签字接受。
- 生产环境、HTTPS、密钥、账号、备份、日志、监控和容量检查完成。
- ERP/WMS 接口、幂等、重试、对账和回退演练完成。
- 培训、操作手册、值守表、升级路径和应急方案完成。

### 9.2 切换步骤

备份和变更冻结 -> 部署版本与迁移 -> 初始化受控配置 -> 接口连通和主数据校验 -> 试生产订单 -> 单件全流程核对 -> 扩大到试点班次 -> 观察期 -> 业务决定继续、修正或回退。

### 9.3 回退原则

应用版本可以回退到兼容版本；数据库不依赖未经验证的自动 Down Migration，必要时从升级前备份恢复。业务回退必须说明在制、扫码、物料和接口消息如何对账，不能只回滚容器镜像。

## 10. 支持与移交

移交包包括：架构和接口文档、配置清单、部署与恢复手册、账号和权限矩阵、监控与日志说明、已知问题、版本记录、培训材料、UAT/验收证据、待现场优化清单。支持期的响应级别、服务时间和责任边界需在真实项目合同中约定，本候选项目不编造 SLA。

## 11. 主要风险与应对

| 风险 | 影响 | 预防/应对 |
|---|---|---|
| 无现场专家导致规则失真 | 做出可运行但不可信的流程 | 证据分级、保持可配置、设置行业评审门禁 |
| ERP 版本/接口能力未知 | 集成范围和工期失控 | 启动阶段完成接口盘点和样例报文验证 |
| 旧代码语义渗透新模型 | 测试全绿但业务仍错误 | 纵向切片替换、旧测试仅作行为记录、新验收先行 |
| 旧数据缺少真实履历 | 迁移后出现伪造谱系 | Legacy 只读，禁止补造事件 |
| 过度追求页面和大屏 | 核心追溯继续缺失 | R5 前冻结非核心 UI，按需求追踪门禁评审 |
| 求职项目长期闭门打磨 | 产出无法及时转化 | 每阶段同步简历故事、方案材料和演示证据 |

## 12. 项目完成定义

项目完成不是“功能清单全部打勾”，而是当前范围内每条 Must 需求都有来源、实现、SQL Server/浏览器测试和证据产物；四条端到端场景可重复；部署与恢复门禁通过；限制和未验证项透明；对外材料不超过实际可信度等级。
