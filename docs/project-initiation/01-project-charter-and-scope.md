## 2. 项目背景

目标工厂画像是一家已有用友或金蝶 ERP、但车间执行仍主要依赖 Excel、纸单和扫码枪的中国中小工业电子制造企业。ERP 能回答计划和财务问题，却不能可靠回答某台工业路由器在何时、按哪个版本、由谁、在何工位、使用了哪些关键件和批次、写入了什么固件、完成了哪些测试，以及异常如何处置。

本项目选择工业路由器整机装配作为唯一业务样板，从已完成上游测试的 PCBA 和其他来料进入整机装配开始，到合格整机完成并向仓储交接为止。SMT、回流焊、AOI、ICT、完整 WMS、APS、OEE 和 PLC 控制均不在首个试点范围。

## 3. 项目愿景

建立一个可部署、可追踪、可解释的单厂 MES 试点候选系统。系统以成品 SN 为核心，将生产订单执行、版本化工艺、物料谱系、固件、测试、质量处置和 ERP 回执连接为一条不可伪造的制造履历，为后续现场验证、效率改进和系统扩展提供可信数据底座。

## 4. 商业问题

- 纸单和 Excel 只能记录局部结果，跨工序、跨角色追溯依赖人工拼接，客诉或召回定位缓慢且容易遗漏。
- ERP 生产订单与车间实际执行之间缺少受控边界，订单变更、耗料、完工和差异处理容易形成多套真相。
- 测试失败、质量保留、返工、复测和报废容易被压缩成单一状态或自由文本，无法证明责任闭环。
- 工艺、BOM、追溯规则和测试规范若随主数据更新而漂移，将无法还原当时实际依据。
- 仅增加经营大屏或页面数量不能修复上述问题，反而可能用漂亮界面掩盖错误业务模型。

## 5. 项目目标

### 5.1 业务目标

1. 通过成品 SN 在分钟级查询到完整制造谱系，并能明确指出缺失或待确认的信息。
2. 让生产订单从 ERP 计划进入 MES 执行后，拥有明确生命周期、冻结执行快照和受控变更路径。
3. 将物料交接、工单发料、实际耗用、退料和冲正分离为可审计事实。
4. 将测试规范、逐项测量、失败、复测、不合格、质量保留、处置和返工分离建模。
5. 通过幂等收件箱和事务发件箱，证明集成消息可以重试、对账和补偿。

### 5.2 工程目标

1. 使用 EF Core Migration 管理 SQL Server 结构，证明空库安装和上一版本带数据升级。
2. 保留快速测试，同时用真实 SQL Server 集成测试覆盖事务、约束、幂等和并发。
3. 形成厂内 Docker Compose 私有化部署、安全配置、备份恢复和升级运行手册。
4. 每个版本形成需求追踪、浏览器流程、谱系导出和工程验证证据包。

### 5.3 求职与能力目标

1. 能以技术型售前视角讲清现状、目标、边界、方案、风险、前置条件和下一步。
2. 能以项目经理视角展示章程、WBS、RACI、RAID、变更控制、UAT 和上线准备。
3. 能以 .NET/MES 工程师视角解释领域模型、事务一致性、集成可靠性和测试策略。

## 6. 成功标准

| 维度 | 技术验证通过的最低标准 | 现场验证前限制 |
|---|---|---|
| 单件追溯 | 固定 SN 可导出订单、快照、工序、物料、固件、测试、质量、完工与回执 | 未经真实产品和工艺人员确认字段充分性 |
| 质量闭环 | 失败记录不可覆盖；返工、复测、处置和解除质量保留有独立事实 | 缺陷码、审批层级和让步规则待确认 |
| 集成 | 重复入站不重复建单；出站失败可重试、回执和对账 | 未完成真实 ERP 版本和接口联调 |
| 数据库 | 新装与升级测试通过；无启动时删库重建 | 未完成真实数据量和停机窗口验证 |
| 一线流程 | 四条核心场景可在浏览器重复执行 | 节拍、扫码设备和工位人体工学待现场验证 |
| 运维 | 生产配置门禁、备份恢复演练、健康检查和日志可查 | RPO/RTO 仍是试点候选目标 |

## 7. 范围

### 7.1 范围内

- ERP 产品、物料和生产订单入站契约及模拟适配器。
- 版本化 BOM、工艺路线、追溯策略和测试规范的执行快照。
- `START_WIP -> ASSEMBLY_BIND -> FW_CONFIG -> FUNCTION_TEST -> FINAL_INSPECTION -> COMPLETE` 参考路线；`PACK_HANDOFF` 按责任配置。
- 成品 SN、关键件 SN、批次 Lot、数量物料的差异化追溯。
- 工位执行、防跳站、物料绑定/解绑、固件/配置记录和制造事件。
- 测试执行、不合格、质量保留、处置、返工、复测、报废和让步接收边界。
- 合格完工、仓储交接、ERP 入账三个可关联但不同的状态。
- 组合角色、职责分离、业务审计、集成对账和单件谱系查询。
- 单厂私有化部署、备份恢复、迁移升级和技术验收证据。

### 7.2 范围外

- 上游 SMT、回流焊、AOI、ICT 等 PCBA 制造过程的虚构或补录。
- APS 高级排产、MRP、完整 WMS、SPC/QMS、OEE、Andon 和设备自动控制。
- 多工厂、多租户 SaaS、Kubernetes、高可用集群和异地灾备。
- 真实用友、金蝶或 SAP 项目联调及厂商认证。
- 财务总账、成本核算、采购销售、总仓波次和库位管理。
- 未经授权生成真实 MAC、IMEI、证书或生产标签号段。

## 10. 治理原则

- 项目章程批准范围；需求台账控制基线；ADR 记录难逆转的架构与领域决策。
- 业务负责人确认“为什么和做什么”，技术负责人确认“如何实现”，质量/关键用户确认“如何证明”。
- 所有变更必须说明业务理由、影响对象、数据迁移、测试和回退，不接受口头插单直接改库。
- 风险、假设、问题和依赖统一进入 RAID 台账，不在聊天记录中失踪。
- 任何生产准备结论必须附证据路径和可信度等级。

## 11. 阶段与里程碑

| 阶段 | 目标 | 退出条件 |
|---|---|---|
| R0 救援基线 | 统一范围、证据、需求和版本门禁 | 文档基线、追踪矩阵、旧声明降级 |
| R1 可信数据底座 | 迁移、安全配置、SQL Server 验证和执行快照 | 新装/升级测试与生产配置门禁通过 |
| R2 制造执行内核 | 订单、身份、路线、事件和物料账 | 从订单到在制的可追踪纵向切片通过 |
| R3 测试质量谱系 | 固件、测试、质量和完整谱系 | 正常、返工复测、报废场景通过 |
| R4 企业集成闭环 | Inbox、Outbox、重试、回执和对账 | 重复、失败和恢复场景通过 |
| R5 一线工作流 UI | 计划、工位、质量和追溯体验 | 浏览器 E2E 与视觉检查通过 |
| R6 可交付与证据 | 部署、恢复、证据包和方案材料 | 技术验证通过；未验证项清单完整 |
