## 2. 需求方法

每条需求使用稳定编号，并在项目管理台账中关联来源、证据等级、业务场景、验收用例、实现版本和证据产物。公开资料无法证明的具体站序、阈值、设备参数和审批层级，不得通过“行业通常如此”直接转成强制需求。

## 3. 现状业务画像

### 3.1 计划与执行断点

ERP 管理产品、物料、计划和财务结果；车间依靠 Excel、纸单和口头协调执行。订单下达后，BOM、工艺、测试要求和实际执行之间缺少可验证快照。ERP 变更若直接覆盖 MES 当前依据，会导致同一工单内不同 SN 无法解释。

### 3.2 追溯断点

成品 SN、关键部件 SN、物料批次、固件版本、工位履历、测试结果和质量处置分散在多个载体。客诉、召回或维修查询需要人工跨表拼接，且无法判断失败记录是否曾被覆盖。

### 3.3 质量断点

测试失败、隔离、处置、返工和复测容易被合并成“当前是否合格”。这会丢失谁发现、依据什么处置、返工做了什么、何时复测以及谁授权解除质量保留。

### 3.4 集成断点

若 ERP 模拟器或真实适配器直接写 MES 数据库，重复消息可能重复建单；若出站消息创建即标记成功，则无法演示超时、重试、回执和对账。制造完工、仓储接收和 ERP 入账也会被错误压成一个状态。

## 4. 目标业务流程

### 4.1 正常路径

1. ERP 通过正式入站契约提交产品、物料和生产订单消息。
2. MES 收件箱进行幂等、版本和载荷校验；失败报文不创建业务订单。
3. 计划员确认订单可执行并下达，系统冻结 BOM、路线、追溯策略和测试规范快照。
4. 物料交接员确认线边交接，并按生产订单发料；发料不等同实际耗用。
5. 成品身份由已授权来源获得，`START_WIP` 将身份与订单和执行快照正式关联。
6. 操作工按当前工位执行装配绑定、固件/配置、功能测试和终检，系统防止跳站。
7. 物料按 SN、Lot 或数量追溯粒度在实际工序记录耗用。
8. 所有必需工序、测试和质量条件满足后，MES 形成合格完工事实。
9. 仓储接收和 ERP 入账通过独立回执关联；对账完成后生产订单关闭。
10. 授权用户按成品 SN 查询并导出完整谱系。

### 4.2 测试失败与返工复测路径

1. 测试执行保留逐项测量和总体失败结果。
2. 系统创建不合格记录并使 SN 进入质量保留，禁止继续正常完工。
3. 质量工程师作出返工处置并引用批准的返工作业或路线版本。
4. 操作工完成返工，系统追加返工事实，不覆盖失败测试。
5. 按处置要求执行复测，形成新的测试执行并关联原失败。
6. 处置条件满足后由授权质量人员解除质量保留，SN 回到允许的执行路径。

### 4.3 报废与短结路径

1. 质量工程师对不合格 SN 作出报废决定并记录依据。
2. 系统追加报废事件、冲正未实际耗用物料，并从正常在制中移除。
3. 已产生在制的生产订单不得直接取消；计划员根据已完工、已报废和未投产数量执行暂停或受控短结。
4. 所有已投产 SN 均有终态且无未决质量保留后，订单才可执行完成。

### 4.4 集成失败与恢复路径

1. MES 在制造事务中同时写入领域状态和待发送 Outbox 消息。
2. 异步发送器发送失败时记录次数、错误和下次重试时间，不伪装成功。
3. 人工或自动重试仍使用同一幂等业务键；外部系统重复回执不重复入账。
4. 对账工作台展示 MES 事实、已发送消息、外部回执和差异处置。

## 5. 业务角色与能力

| 角色 | 核心能力 | 明确禁止 |
|---|---|---|
| 计划员 | 接收、排定、下达、暂停、短结和关闭生产订单 | 修改 ERP 权威主数据、批准质量处置 |
| 操作工 | 扫码、装配绑定、固件/配置、测试和缺陷报告 | 批准工艺、修改测试规范、解除质量保留 |
| 产线主管 | 查看本线执行和异常、协调生产、发起暂停 | 替代计划员下达、替代质量工程师处置 |
| 工艺工程师 | 维护并批准路线、作业、追溯和测试规范版本 | 直接改写已投产 SN 的执行依据 |
| 质量工程师 | 不合格评审、返工/报废/让步处置和解除保留 | 修改原始测试结果、无依据放行 |
| 物料交接员 | 物料交接、工单发料、退料和成品移交 | 完整 WMS 库位、波次和财务库存操作 |
| 系统管理员 | 账号、组合角色和技术配置 | 天然拥有所有业务审批权限 |
| 运营负责人 | 只读查看订单、在制、测试和质量异常 | 执行或审批生产业务 |

## 6. 功能需求

### 6.1 主数据与执行快照

- **FR-MD-001**：系统必须通过正式集成契约接收 ERP 权威的产品、物料、计量单位和生产订单数据，记录来源版本与校验结果。
- **FR-MD-002**：工艺路线、追溯策略、工位、作业参数和测试规范必须采用受控版本，并保留批准状态和生效范围。
- **FR-MD-003**：生产订单下达时必须生成可独立还原的执行快照，不能只保存源记录 ID 或版本字符串。
- **FR-MD-004**：模板变更不得影响已投产 SN；订单变更必须形成受控版本、影响分析和审计记录。

### 6.2 生产订单

- **FR-PO-001**：订单采用 `已接收 -> 已下达 -> 生产中 <-> 已暂停 -> 执行完成 -> 已关闭`；仅未投产订单允许取消。
- **FR-PO-002**：入站校验失败不得创建生产订单；重复消息不得重复建单。
- **FR-PO-003**：暂停必须阻止新的投产和正常过站，同时保留既有在制、质量和耗料责任。
- **FR-PO-004**：执行完成必须校验全部已投产 SN 已合格完工或报废，且不存在未决质量保留。
- **FR-PO-005**：关闭必须校验 ERP/WMS 回执、对账和差异处置完成，并将订单转为只读。

### 6.3 产品身份与在制

- **FR-ID-001**：成品 SN、MAC、IMEI、证书等身份必须记录来源、分配状态和关联历史；MES 只能使用获授权的发号方或号池。
- **FR-ID-002**：`START_WIP` 必须将成品身份、生产订单、产品和执行快照正式关联并形成制造事件。
- **FR-WIP-001**：系统必须维护每个成品 SN 的当前执行位置、质量保留和终态，同时保留全部历史事件。
- **FR-WIP-002**：只有当前应执行工序与工位能力一致时才允许过站；跳站请求必须被拒绝并说明原因。
- **FR-WIP-003**：绑定、解绑、换标、补打和更正必须追加事件并引用被更正事实，不得覆盖历史。

### 6.4 物料执行

- **FR-MAT-001**：物料交接、工单发料和实际耗用必须作为三个独立业务事实。
- **FR-MAT-002**：序列件在绑定具体部件 SN 时耗用；批次件记录 Lot 和数量；数量件按批准规则在指定工序回冲。
- **FR-MAT-003**：当前线边余额和工单可用量必须由只追加物料事务投影，禁止直接改写总数或形成负库存。
- **FR-MAT-004**：退料、冲正和调整必须使用反向或补偿事务，并记录原因、主体和关联原事务。
- **FR-MAT-005**：成品谱系必须能显示逐件、批次和数量三种追溯粒度的投入关系。

### 6.5 固件、配置和测试

- **FR-FW-001**：固件/配置执行必须记录包或配置标识、版本、校验值、设备/工具、操作主体、时间和结果。
- **FR-TEST-001**：测试规范必须定义项目、数据类型、单位、判定限、必测条件和版本。
- **FR-TEST-002**：每次测试必须形成独立执行记录，包含逐项测量、设备/夹具、起止时间、总体结果和原始报告引用。
- **FR-TEST-003**：复测必须追加新记录并关联原失败，不允许将失败记录修改为通过。
- **FR-TEST-004**：缺少必测项目、测量超限或存在未决质量保留时不得合格完工。

### 6.6 质量闭环

- **FR-QA-001**：测试或操作发现不符合要求时，系统必须创建不合格记录并进入质量保留。
- **FR-QA-002**：质量处置必须由授权人员选择返工、报废或让步接收，并记录理由与依据。
- **FR-QA-003**：返工必须引用批准的返工作业或路线版本，并明确所需复测。
- **FR-QA-004**：解除质量保留必须引用不合格记录、处置决定和完成证据，不接受自由文本“放行”。
- **FR-QA-005**：报废必须形成终态、数量和物料责任变化，不得删除原执行事实。

### 6.7 完工、交接与谱系

- **FR-CMP-001**：合格完工必须校验路线、测试、身份、质量和必要物料条件，并形成制造事件。
- **FR-CMP-002**：MES 合格完工、仓储接收和 ERP 入账必须使用不同状态和可关联业务键。
- **FR-TRC-001**：按成品 SN 查询必须返回订单、执行快照、工序、物料、固件、测试、质量、完工、交接和集成回执。
- **FR-TRC-002**：谱系必须显示更正、冲正、解绑和复测的前后关系，而不是只显示最终结果。
- **FR-TRC-003**：谱系导出必须包含生成时间、数据版本、查询条件和证据缺口说明。

### 6.8 企业集成

- **FR-INT-001**：入站收件箱必须记录来源、消息 ID、业务键、消息类型、版本、原始载荷校验和处理结果。
- **FR-INT-002**：领域状态和出站消息必须在同一数据库事务中提交。
- **FR-INT-003**：出站消息必须支持 Pending、Processing、Sent、Failed 和 DeadLetter，以及自动/人工重试。
- **FR-INT-004**：系统必须提供回执关联、差异展示、人工补偿和对账证据。
- **FR-INT-005**：ERP 模拟适配器必须走与真实适配器相同的 Inbox/Outbox 和回执流程，禁止直写业务表。

### 6.9 权限、审计与运营查询

- **FR-SEC-001**：账号必须支持组合业务角色，默认工作台不得代替服务端授权。
- **FR-SEC-002**：关键职责必须分离；系统管理员不能天然获得工艺和质量审批权。
- **FR-AUD-001**：关键业务动作必须记录主体、时间、对象、动作、理由和关联业务键。
- **FR-OPS-001**：授权角色必须能查看生产订单进度、在制分布、未决质量保留和集成异常，并下钻到单件事实。
- **FR-OPS-002**：聚合指标必须来自执行事实，不接受无来源的手工填报或装饰性大屏。

## 7. 非功能需求

- **NFR-DATA-001**：制造事件、测试执行、质量处置和物料事务必须只追加；更正通过引用原记录的新事实表达。
- **NFR-CONS-001**：单个制造动作的规则校验、当前状态、制造事件和 Outbox 必须具备事务一致性。
- **NFR-DB-001**：SQL Server 架构只通过 EF Core Migration 演进，正式启动不得自动删库或装载演示数据。
- **NFR-TEST-001**：每个发布版本必须通过 SQLite 快速回归与真实 SQL Server 关键集成测试。
- **NFR-SEC-001**：正式环境必须使用 HTTPS、外置密钥、最小权限数据库账号、受限来源和非演示账号初始化。
- **NFR-OPS-001**：系统必须提供不泄密的存活/就绪检查、结构化日志、请求关联 ID 和关键任务告警入口。
- **NFR-REC-001**：试点候选恢复目标为 RPO 24 小时、RTO 4 小时，必须通过一次备份恢复演练验证；现场可重新约定。
- **NFR-PERF-001**：扫码和过站交互目标、并发工位数、事件量和谱系查询时间必须在现场容量工作坊后基线化；当前不得伪造固定性能承诺。
- **NFR-RET-001**：制造、审计、测试原始文件和个人信息的保存年限必须可配置，并由合同、客户和法规要求决定。
- **NFR-USAB-001**：工位端必须扫码优先、明确显示当前工位/工序和拒绝原因，并通过实际操作走查验证。

## 8. 数据与报表需求

首期不建设完整报表中心。必须提供的查询是：生产订单状态与数量平衡、成品 SN 全谱系、当前在制位置、未决质量保留、测试执行与复测链、物料事务和集成消息对账。所有汇总必须可下钻到业务事实。

## 9. 业务规则摘要

- ERP 是产品、物料、计量单位、生产订单和计划数量的权威；MES 是执行规则与制造事实的权威。
- 下达时冻结执行快照；投产后的 ERP 变更不能静默覆盖。
- 生产订单有在制后不能取消；暂停和短结必须保留责任。
- 测试失败不等于质量处置；质量保留不等于报废；解除保留不等于修改原结果。
- 发料不等于耗料；合格完工不等于仓储接收；仓储接收不等于 ERP 入账。
- 自动化测试证明实现符合已定义规则，不证明规则已被真实工厂接受。

## 10. 待现场确认

1. 实际产品族、BOM 层级和关键件/批次件清单。
2. 成品 SN、MAC、证书和标签的来源、格式、号池责任及重打规则。
3. 实际装配顺序、返工点、包装责任和工位配置。
4. 功能测试项目、阈值、设备/夹具、原始文件格式和自动采集方式。
5. 缺陷码、MRB/质量审批层级、让步接收和报废授权。
6. ERP 产品、版本、接口方式、主数据和完工/耗料/报废单据类型。
7. 产量、班次、并发工位、峰值扫码、单 SN 事件量和查询目标。
8. 数据保留、个人信息、证书密钥、网络分区、备份和灾备要求。

## 11. 需求批准

真实项目应由业务负责人、工艺、质量、计划、仓储、ERP/IT 和实施方联合评审。未获得签字前，本文状态保持“候选基线”，不得作为合同范围或上线承诺。
