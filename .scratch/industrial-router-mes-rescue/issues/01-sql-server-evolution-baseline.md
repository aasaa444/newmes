# 01 — 建立可演进的 SQL Server 数据库基线

**What to build:** 让实施和运维人员可以用同一套受控机制安装全新的 MES 数据库、升级保留已有数据的旧数据库，并按显式命令装载非生产演示数据。应用启动不得再自动建库、猜测结构、删除数据库或重建数据库。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 空 SQL Server 数据库可以通过版本化 Migration 安装到当前结构，随后应用进入就绪状态。
- [ ] 上一版本且包含代表性旧数据的数据库可以升级，原有可证明数据保持可读，无法证明的新制造事实不会被补造。
- [ ] 应用启动只检查数据库兼容性；数据库缺失、版本落后或 Migration 失败时给出明确错误并拒绝就绪。
- [ ] 所有自动建库、自动删库重建和基于运行时结构猜测的路径均退出正式启动流程。
- [ ] 身份、主数据和演示订单只能通过显式的非生产初始化命令装载，正式环境默认不装载。
- [ ] 真实 SQL Server 测试同时覆盖空库安装、带数据升级、约束、事务失败回滚和重复执行 Migration。
- [ ] SQLite 可以保留为快速反馈工具，但发布结果明确区分 SQLite 与 SQL Server 证据。
- [ ] 升级和回退说明包含升级前备份要求，且失败不会修改为一个看似可用但不完整的数据库。
