# 20 — 生成版本化技术验证证据包

**What to build:** 让项目经理、售前工程师、面试官或后续评审人能够独立核对这个候选版本实现了什么、如何验证、有哪些限制，并得出不超过现有证据等级的可信结论。

**Blocked by:** 18 — 固化唯一高层验收接缝; 19 — 私有化部署、升级与恢复演练.

**Status:** ready-for-agent

- [ ] 证据包记录版本、提交、构建环境、数据库版本、执行时间和生成主体。
- [ ] 每条 Must 需求关联至少一个自动测试或人工验收步骤；未覆盖项记录原因、风险和责任人。
- [ ] 包含领域/API、真实 SQL Server、契约、浏览器、安全、部署和恢复测试结果及失败说明。
- [ ] 包含四组高层场景的输入、关键用户操作证据、机器结果和固定 SN 完整谱系导出及校验值。
- [ ] 包含空库安装、带数据升级、权限拒绝、配置门禁、备份恢复和恢复后冒烟证据。
- [ ] Critical 缺陷为零；损害制造事实或追溯的 Major 缺陷为零，其他遗留缺陷有明确处置。
- [ ] 已知限制、未验证业务假设、现场发现项和真实 UAT 前置条件完整列出。
- [ ] 可信度按“未验证、已实现、技术验证通过、制造从业者评审通过、真实现场验证通过”评定，并附升级依据。
- [ ] 在没有制造评审和工厂试运行证据时，结论最高为“技术验证通过”，不得使用已上线、已验收或真实落地表述。
- [ ] 证据包由未参与实现的人按说明复核，能够重复得到关键测试和校验结果。
