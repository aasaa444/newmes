# 15 — 事务 Outbox、ERP 回执、对账与关单

**What to build:** 让 MES 在完工、耗用/冲正、报废和交接等业务事实发生时可靠地产生出站消息，并让 IT 与计划员处理失败、回执和对账；只有跨系统差异完成处理后订单才能关闭。

**Blocked by:** 04 — ERP 幂等生产订单入站; 06 — 线边物料交接与工单发料事务账; 13 — 终检与制造完工门禁; 14 — 成品仓储交接.

**Status:** ready-for-agent

- [ ] 需要外发的领域状态和 Outbox 消息在同一个 SQL Server 事务中提交，任一失败均整体回滚。
- [ ] 消息管理 Pending、Processing、Sent、Failed 和 DeadLetter，并保留每次尝试、错误和下次重试时间。
- [ ] 多个发送器并发时只有一个能够在租约内认领同一消息，租约失效后可安全恢复。
- [ ] 模拟 ERP 通过正式契约接收消息并按业务幂等键去重，不能直接修改 MES 状态。
- [ ] ERP 回执与原消息和业务对象关联，明确区分发送成功、对方接受和对方入账。
- [ ] 授权用户可以查看失败/死信、执行人工重试或登记受控补偿，所有动作形成审计。
- [ ] 对账工作台展示订单的完工、耗用、报废、仓储与 ERP 差异及处理状态。
- [ ] 订单只有在全部 SN 已终结、无质量保留、必要仓储/ERP 回执完成且差异关闭后才能“已关闭”。
- [ ] 测试覆盖暂时失败、永久失败、重复投递、重复回执、并发认领、人工重试和对账前关单拒绝。
