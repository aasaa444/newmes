# 18 — 固化唯一高层验收接缝

**What to build:** 让未参与实现的人可以通过真实浏览器和公共 API，在真实 SQL Server 上重复执行同一条制造闭环，并用正常、返工、报废和集成失败四组场景证明系统的外部行为。

**Blocked by:** 17 — 收缩并隔离旧执行路径.

**Status:** ready-for-agent

- [ ] 使用稳定且互不复用的订单号、成品 SN、关键件 SN、Lot、消息 ID 和测试运行 ID 准备四组非生产数据。
- [ ] 正常场景覆盖订单入站、快照、物料、投产、装配、固件、测试、终检、完工、仓储、ERP、关单和谱系导出。
- [ ] 返工场景保留原失败测量，覆盖不合格、质量保留、返工决定、返工作业、复测和受控解除保留。
- [ ] 报废场景覆盖质量报废、物料责任/冲正、取消拒绝、订单数量平衡和受控执行完成。
- [ ] 集成场景覆盖重复 Inbox、Outbox 暂时失败、并发认领、自动/人工重试、幂等回执和对账前关单拒绝。
- [ ] 每个场景通过真实浏览器完成关键角色操作，通过公共 API 获取机器可校验结果，不直接写业务数据库。
- [ ] 测试运行在临时真实 SQL Server 上并从 Migration 建库；SQLite 结果不替代该接缝。
- [ ] 失败输出能够定位到具体业务步骤、关联 ID、角色和预期，不以截图人工猜测作为唯一诊断方式。
- [ ] 四组场景统一属于一个高层验收接缝，低层测试作为支撑而不形成第二套完成口径。
