# 05 — 生产订单下达、执行快照与受控生命周期

**What to build:** 让计划员把已接收订单下达为稳定的车间执行依据，并在暂停、恢复、取消、执行完成和关闭之间遵循可审计状态机。模板后续变化不得改变已下达订单和在制产品的执行规则。

**Blocked by:** 04 — ERP 幂等生产订单入站.

**Status:** ready-for-agent

- [ ] 只有完整且处于“已接收”的订单能够下达；下达操作生成不可原地改写的执行快照。
- [ ] 快照自包含产品、单层 BOM、路线及工序、追溯粒度、身份策略、固件要求、测试规范和完成门禁的版本化依据。
- [ ] 模板在下达后创建新版本不会改变旧订单快照或引用该快照的 SN。
- [ ] 状态遵循“已接收 -> 已下达 -> 生产中 <-> 已暂停 -> 执行完成 -> 已关闭”，非法转换返回明确拒绝。
- [ ] 只有尚未投产的订单可以取消；已投产订单的来源变更不得静默覆盖原快照。
- [ ] 计划员可以看到计划数、投产数、合格数、报废数、未投产数和在制数，并满足数量平衡。
- [ ] 暂停状态为后续投产和过站提供强制门禁；执行完成与关闭分别保留制造和跨系统边界。
- [ ] 工作台显示订单状态、快照版本和可执行命令；每次状态变更形成审计记录。
- [ ] 状态机、快照不变性、并发下达和非法转换在公共 API 与真实 SQL Server 上验证。
