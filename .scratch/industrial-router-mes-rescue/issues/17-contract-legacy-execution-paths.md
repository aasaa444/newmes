# 17 — 收缩并隔离旧执行路径

**What to build:** 在新的订单、制造、质量、集成和谱系路径全部可用后，移除能够绕过新规则的旧写入入口，并把无法可信迁移的旧记录清晰隔离为 Legacy 只读历史，而不是为追求完整外观补造数据。

**Blocked by:** 16 — 完整单件谱系与召回反查导出.

**Status:** ready-for-agent

- [ ] 盘点所有旧工单、过站、简单放行、直接入库、模拟出站和数据库初始化写入路径，并为每项确定迁移、只读或删除结论。
- [ ] 所有用户工作流和模拟适配器已经切换到新公共契约，旧写接口不再有活跃调用者。
- [ ] 旧数据中可证明的身份、工单、过站、绑定和结果保持可读，并明确标记来源和可信限制。
- [ ] 无法从旧记录证明的执行快照、Lot、固件、逐项测量、质量处置和回执保持未知，不使用默认值补造。
- [ ] 可绕过执行快照、物料事务、质量门禁、Outbox 或职责分离的旧写入口被移除或永久拒绝。
- [ ] Legacy 查询不会与新模型数据混合成看似完整的制造履历，对用户显示限制说明。
- [ ] 现有旧测试按新契约重写或明确归档为行为记录，发布测试不再依赖错误业务语义。
- [ ] 收缩后全部新流程和迁移测试保持通过，且数据库升级不删除旧证据。
