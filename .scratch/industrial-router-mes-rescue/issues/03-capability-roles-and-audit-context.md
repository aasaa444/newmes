# 03 — 建立可组合角色与业务审计上下文

**What to build:** 让单厂用户可以按实际兼岗组合业务角色，同时保证操作、计划、工艺、质量、物料和系统管理之间的关键职责分离；每次受控业务动作都能说明是谁以什么权限做了什么。

**Blocked by:** 01 — 建立可演进的 SQL Server 数据库基线.

**Status:** ready-for-agent

- [ ] 账号可组合计划员、工艺工程师、操作工、产线主管、质量工程师、物料交接员、系统管理员和运营负责人等角色。
- [ ] 服务端按具体业务能力授权，主角色只决定默认工作台，不替代能力检查。
- [ ] 操作工不能批准质量处置或解除质量保留，产线主管不能替代质量审批，系统管理员不因技术权限自动获得业务审批权。
- [ ] 管理员可以停用账号和调整角色；变更立即影响后续授权，并形成不可由普通接口删除的审计记录。
- [ ] 登录身份、有效角色和能力可由前端查询，以便显示正确工作台和命令入口。
- [ ] 关键成功和拒绝动作记录主体、角色语义、时间、关联 ID、业务对象和结果，且不把制造事件与管理审计混为一表。
- [ ] 权限矩阵测试覆盖每个角色的主要允许与拒绝路径；隐藏按钮不作为授权通过的证据。
